# KERNEL: Six Prompt Engineering Patterns

A carousel summarizing the "KERNEL" prompt-writing framework, adapted from a Reddit post by a tech lead, with a worked before-and-after coding example. The full prompt is only offered through a comment request.

Written by claude-haiku-5-5.

## What it teaches

1. K (Keep it simple): use one clear goal instead of long context, and be specific (e.g., 'Write a technical tutorial on Redis caching' rather than 'help me with something about Redis').
2. E (Easy to verify): give the prompt clear success criteria, replacing vague asks like 'make it engaging' with checkable ones like 'include 3 code examples'.
3. R (Reproducible results): avoid time-relative wording such as 'current trends' or 'latest best practices', and use specific versions and exact requirements so the prompt works again later.
4. N (Narrow scope): one prompt, one goal; don't combine code, docs and tests in one request; split complex tasks into separate prompts.
5. E (Explicit constraints): tell the AI what NOT to do and add limits, e.g., 'Python code. No external libraries. No functions over 20 lines.'
6. L (Logical structure): format every prompt as Context (input), Task (function), Constraints (parameters), Format (output).
7. Advanced tip: chain several focused prompts instead of writing one complex prompt, so each does one thing well and feeds into the next.

### Key steps

1. Keep it simple: one clear, specific goal (e.g. 'Write a technical tutorial on Redis caching').
2. Easy to verify: state checkable success criteria (e.g. 'include 3 code examples').
3. Reproducible: avoid 'latest' or 'current' wording and name exact versions.
4. Narrow scope: one prompt per goal. Split code, docs and tests into separate prompts.
5. Explicit constraints: say what not to do (e.g. 'Python only, no external libraries, no function over 20 lines').
6. Logical structure: write each prompt as Context, Task, Constraints, Format.
7. Chain several focused prompts, each feeding the next, instead of one complex prompt.
