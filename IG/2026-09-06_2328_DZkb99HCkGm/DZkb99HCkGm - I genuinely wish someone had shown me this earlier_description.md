# Coding interview patterns repo and code tips

A reel that praises a GitHub repo for learning coding interview patterns instead of memorizing LeetCode solutions, with a bad-versus-good code comparison and a handwritten sliding window sum example. The repo is only called "algorithm patterns" and no link is shown.

Written by claude-haiku-5-5.

## What it teaches

1. Name variables and functions descriptively (for example calculate_order_total with base_price, quantity and tax_rate instead of calc_total with price, qty and t).
2. Put magic numbers such as the discount quantity threshold and discount rate into named constants instead of hard-coding them.
3. For a sliding window of fixed size k, reuse the previous window's sum: subtract the element that leaves the window and add the element that enters it, rather than re-summing the whole window.

## Caption

I genuinely wish someone had shown me this earlier.

Most people prepare for coding interviews by solving hundreds of random LeetCode questions and hoping something sticks. This repo takes a completely different approach: it focuses on the patterns behind the problems.

Instead of memorizing solutions, you learn concepts like sliding windows, two pointers, binary search, backtracking, dynamic programming, and other techniques that show up again and again in interviews.

Once you start recognizing the patterns, a lot of questions stop feeling random and start feeling familiar.

If coding interviews have ever felt overwhelming, this is one of those resources that’s absolutely worth bookmarking.
