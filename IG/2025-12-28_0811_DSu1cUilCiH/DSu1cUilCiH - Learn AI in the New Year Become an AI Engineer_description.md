# Become an AI Engineer: Cohort 3 Course Outline

A course announcement for Cohort 3 of "Become an AI Engineer," with a graphic listing six hands-on projects and two learning tracks. The caption describes the cohort's hands-on, mentored, community-based format.

Written by claude-haiku-5-5.

## What it teaches

1. Project 1: Build an LLM playground. Cover LLM foundations, pre-training (data collection, data cleaning, tokenization, architectures such as Transformers, GPT and Llama families, text generation with greedy/beam search, top-k and top-p), then post-training (SFT, RL and RLHF).
2. Project 2: Build a customer support chatbot. Cover adaptation techniques (PEFT, adapters, LoRA) and prompt engineering (few-shot and zero-shot, chain-of-thought, role-specific and user-context prompting).
3. Project 3: Build an 'ask-the-web' agent similar to Perplexity. Cover agents vs. agentic systems vs. LLMs, agency levels, and workflow patterns (prompt chaining, routing, parallelization, reflection, orchestrator-worker).
4. Project 4: Build a 'deep research' capability. Cover reasoning models (such as OpenAI's o-family and DeepSeek-R1), inference-time scaling, CoT prompting, self-consistency, sequential revision, and Tree of Thoughts.
5. Project 5: Build an image generation service. Cover image and video generation approaches (VAE, GANs, auto-regressive, diffusion) and text-to-image work: data preparation, diffusion architectures (U-Net, DiT), training and sampling.
6. Project 6: Capstone project. Choose your own idea, build it with techniques from the course, then present a demo and get feedback.
7. Learning track: Agents and RAG. Cover query decomposition, context engineering, memory, meta-agent vs. planner vs. orchestrator patterns, feedback loops, single-agent vs. multi-agent vs. hierarchical agentic RAG, multimodal RAG, and context management.
8. Learning track: MCP and A2A. Cover MCP vs. normal API tooling, MCP clients and servers, tool and resource discovery, prompt injection via MCP, A2A definition, AgentCards and capability discovery, latency/communication overhead, and compatibility and versioning.
